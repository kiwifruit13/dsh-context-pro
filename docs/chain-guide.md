# 链感知：使用与架构指南

> 面向**使用者**（配置插件的人）与**开发者**（维护/扩展系统）。
> 终局共识（设计方案与规划.md）：CoT 放权——从"指令驱动"降级为"上下文浸泡"。

---

## 一、这是什么

DSH-Context-Pro 的链感知能力，让对话中的推理结构（因果/逻辑/操作/叙事/时间）被
**模型自然感知并在末尾通过 JSON 快照隐式标记**，成为高密度、可回溯、随对话演化的上下文。

```
对话中模型感知链形态 → 回复末尾输出 JSON 快照 → hook 提取为 ChainNode
→ 会话内 ChainGraph → SELECT 优先注入
→ 用户看到纯自然语言（JSON 行被 hook 自动剥离）
→ 会话结束/删除 → 链一并清除（不残留）
```

**关键设计决策**：模型正文中**不出现任何 `[因果@1]` 标签或节点名抬头**。
用户感受不到框架的存在，只感受到逻辑清晰、节奏自然的对话。

---

## 二、启用方式（配置）

```yaml
# cordis.patch.yml 或 cordis.yml 中 context-pro 的 config
config:
  chains:
    enabled: true          # 开启链感知（默认 false）
    injectProtocol: true   # 注入图鉴提示词段（让模型内化五链结构）
    stripAnchors: true     # 注入前剥离残留锚点（兼容旧会话）
    maxNodesPerChain: 20   # 每链节点上限（防演化失控）
```

> 推荐：`enabled: true` + `injectProtocol: true` 一起开。`stripAnchors` 仅用于兼容旧会话中可能残留的 `[因果@1]` 标签。

## 三、五链认知图鉴（模型感知结构）

| 链 | 结构 | 自然触发场景 | 模型口吻 |
|----|------|-------------|----------|
| 因果 | 问题→原因→方案 | 异常/困境 + "为什么" | 侦探感：先表象→层层剥根因→手术刀式方案 |
| 逻辑 | 前提→推理→结论 | 权衡/假设/"如果…那么…" | 冷峻："因为1、2、3，所以A" |
| 操作 | 动作→步骤→结果 | 动作动词/"先…再…" | 说明书：编号+具体动词+坑标注 |
| 叙事 | 开端→发展→转折→结局 | 具体年月/状态反转/回顾 | 画面感：转折点高亮为信息最高密区 |
| 时间 | 过去→现在→未来 | "以前/现在/以后"三段对比 | 标注时间刻度：短/中/长期 |

**判断口诀**：这段内容"解释因果"→因果；"推出结论"→逻辑；
"给出步骤"→操作；"讲了一个过程"→叙事；"对比时态"→时间。

## 四、模型如何打标（内部协议）

模型不需要在正文中输出任何标签，只需在回复**末尾最后一个非空行**输出一行 JSON：

```json
{"chain":"因果链","nodes":{"问题":"项目延期","原因":"需求失控","方案":"裁剪优先级"}}
```

### 节点值三种形态

| 形态 | 示例 | 场景 |
|------|------|------|
| 字符串 | `"需求失控（置信度78%）"` | 推断结论，可括注把握度 |
| 分叉 | `{"ai":"人力不足","user":"需求混乱"}` | 与用户路径分歧，并行记录 |
| 合流 | `{"value":"优先级裁剪","from":["ai","user"],"confidence":0.8}` | 双方推论在下游重叠 |

### 推翻旧主链

```json
{"chain":"因果链","supersede":{"root":1,"reason":"新证据：人力充足"},"nodes":{"问题":"项目延期","原因":"需求失控"}}
```

被推翻的旧结论保留为"曾以为"（supersede），供对比论证引用。

### 未识别

```json
{"chain":"null"}
```

## 六、模型如何受益（两大用途）

### 用途 A：快速回溯前文

```
用户：我们之前怎么解决注入问题的？
模型（推理）："需要找回因果链" → SELECT 从 ChainGraph 选 causal 活跃节点 → 注入
回复：我们最终发现是 scope 包装拓宽了 next 返回类型，解决方案是显式展平……
```

### 用途 B：压缩时保留语义骨架

```
压缩前：多轮原始对话（长）
压缩中：ChainGraph 提供活跃链结构 → 压缩器保留"问题→原因→解决"骨架
压缩后：对话被压缩，但链骨架仍在 → 模型可引用展开
```

## 七、最佳实践

| 场景 | 建议 |
|------|------|
| 长程任务（多轮迭代） | 开链感知——跨轮回溯靠链，不靠重读全文 |
| 压缩前 | 让模型先感知再压缩——链是语义锚 |
| 复杂问题（多因/反复修正） | 鼓励模型在 JSON 中用 supersede 记录演化史 |
| 简单问答（单轮） | 可关链感知（enabled: false）——省 token |
| 模型不输出 JSON | 属于正常退化——SELECT 回退到纯文本注入 |

## 八、已知边界

- 链是**会话内临时**：删对话即删链，不跨会话（跨会话用 agent-memory 长期记忆）
- 模型不输出 JSON 快照 → 链感知退化为纯文本 SELECT（软信号设计）
- 每链节点上限 20（maxNodesPerChain 可调）——防演化失控
- `injectProtocol` 只影响**新会话**的模型（提示词段在每次组装时注入）
- 末尾 JSON 行由 hook 自动剥离，用户不可见；如需验证，查看 session 日志原始消息
- 锚点语法（[因果@1]）已下线并删除，解析器不再保留；模型仅通过末尾 JSON 快照输出结构化结论
